# EXP-2026-0012 Paper Runbook

## Scope

EXP-2026-0012をBTC/JPY日足で仮想運用する。実注文、取引所資格情報、レバレッジ、short、
自動増額は使わない。開始時仮想資金は10,000 JPYで、固定設定は
`config/strategies/exp-2026-0012-paper.yaml`を正本とする。

paperの目的は、利益だけでなく次を未来の確定日足で確認することである。

- SMA200付きDonchian entryとATR trailing exitの発火
- signal確定後、次日始値での仮想約定
- fee、spread、slippage控除後の現金・数量・equity
- stopのラチェット、再entry待ち、最大DD
- 再起動時の状態引継ぎと同一日足の重複防止

## Input contract

入力はUTC日足CSVとし、最低365日のwarm-upを含める。

```text
event_time,open,high,low,close,is_interpolated
```

価格はBTC/JPYで統一する。未確定日足、重複、欠損、時刻逆行を入力しない。
`is_interpolated=true`の日に注文が必要になった場合は約定せず停止する。

## Run

```bash
uv run python scripts/download_binance_btcjpy_daily.py
uv run python scripts/run_exp_2026_0012_paper.py \
  --bars data/paper/BTCJPY-1d.csv
```

取得処理はBinance Spotの認証不要REST APIだけを使用し、当日の未確定日足を除外する。
API keyやaccount endpointは使用しない。

既定のローカル出力はGit管理外に置く。

- 状態: `var/paper/EXP-2026-0012/state.json`
- 不変台帳: `var/paper/EXP-2026-0012/ledger.jsonl`

同じCSVで再実行しても、処理済み日足は再約定しない。状態や台帳を削除して運用履歴を
初期化してはならない。試験をやり直す場合は別の一時パスを指定する。

## Daily review

runner出力と台帳から次を確認する。

1. `live_orders_sent`が常に0である。
2. `halted`と`halt_reasons`を確認する。
3. 最終event time、現金、BTC数量、equityを前日状態と照合する。
4. signalがあれば、確定日の翌日始値でfillされていることを確認する。
5. 補間日、重複日足、上限超過、日次損失、DD停止を確認する。

初回レビューはpaper開始から30日経過時、または最初の1往復完了時の早い方で行う。
取引がなくても失敗とはしないが、出口性能を確認したとは扱わない。

## Scheduling

Windowsタスク`CryptAI-EXP-2026-0012-Paper`から、毎日09:10（日本時間）に
`scripts/run_paper_daily.sh`を起動する。ジョブは`flock`で多重起動を拒否し、ログを
`logs/paper/YYYY-MM-DD.log`へ保存する。PC停止などで実行できなかった日は、次回実行時に
公開APIから不足日足をまとめて取得し、状態ファイルより後のバーだけを処理する。

スケジュール登録は実注文許可ではない。タスクの実行内容には公開市場データのGETと
ローカルpaper会計しか含めない。

## Stop and rollback

停止時はrunnerを実行せず、状態と台帳を保存する。再開前に停止理由と残高を照合する。
設定の緩和、状態の手修正、資金の自動追加は行わない。戦略を撤回する場合はapprovalを
`halted`へ変更する別PRを作る。shadowまたはliveへの移行も別承認とする。
